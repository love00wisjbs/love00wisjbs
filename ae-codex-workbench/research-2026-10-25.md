## 从工作流提取的可复用原则（调研笔记，尚非已验证 skill）
1. 先读取当前工程、目标合成、选中图层和必要属性；按需展开，不每次导出整个工程。
2. 明确目标合成，遇到同名、缺失或无活动合成时停止写入；不静默扩大为全工程。
3. 区分 ExtendScript 的 ES3 约束与 AE 表达式引擎能力；脚本用 var、1-based 图层索引及 matchName。
4. 写入前保存工程副本；更改使用 try/finally 闭合 undo group。撤销组不是事务，外部文件写入、渲染及部分失败仍需单独处理。
5. 批量重命名、素材重链接、字体替换、表达式替换先列出计划与影响范围，再执行已授权范围。
6. 先少量样本验证再批量；重跑前检查已有对象，防止重复合成或关键帧。
7. 渲染前检查缺失素材、字体、表达式错误、输出模块、分辨率、帧率、色彩与 alpha；先短预览，再全长输出。
8. 执行结果、实际渲染文件和视觉验收分别记录。只有生成 JSX 不能称 AE 中执行成功。

## 推荐的手机 → Windows 设计草案（待用户选择与确认）
推荐先建立可移植技能包，以 Windows 本地 AE 为执行端。手机负责需求、调研、代码审阅和 GitHub 存储；Windows 拉取同一提交后执行 JSX。第一版保留 AE 菜单 File > Scripts > Run Script File 的手动入口，避免把 MCP 连接当成必要条件；验证通过后再接本地 MCP。
备选：先直接安装现有 AE MCP，联机交互更方便，但依赖本地客户端和桥接面板，手机当前无法验证。

拟交付目录：
- skills/after-effects-windows/SKILL.md：触发条件、查询→计划→执行→验收流程。
- references/：来源、版本限制、工作流笔记。
- scripts/：经过审查的最小 JSX 示例，不直接复制 macOS runner。
- docs/windows-handoff.md：Windows 安装、运行、验收与失败恢复。
- docs/progress.md：已完成、待验证、下一步和提交标识。
后续运行需 Windows、已安装且授权的 AE、具体版本与本地素材；云端 Linux 不能验证 AE 渲染。
